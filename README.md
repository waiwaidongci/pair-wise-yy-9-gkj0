# 古法蓝晒 · 转手链整理室

两个工位同时处理同一块玻璃板：晚到的人会把盒位和药液占用盖掉。本系统把**玻璃板 → 工艺检查点 → 入盒批次**接成一条可恢复的转手链，保证：

- **一板一工位持有**：工位认领后拿到 30s 租约，租约内别的工位不能覆盖（晚到者收到 `held_by_other`）。
- **过期从最近检查点续做**：租约过期后任意工位可接管，从最近一个有效检查点继续，不重头来。
- **药液批次失效重排**：更新药液批次会让旧的显影结论（及冲洗之后的连带步骤）失效、释放持有、重新排队，并从最近检查点续做。
- **写盘失败按检查点重试**：存储层原子写（临时文件 + rename），可注入写盘故障；事务在内存改 → 落盘，失败则回滚到上一个持久快照再重试。
  - 消耗幂等：消耗凭证 = `板:步骤:批次`，重试不重复扣药液。
  - 持有与完成同生共死：持有与检查点在同一事务落盘，不留下"已占用却没完成记录"的中间态。
- **页面 / 接口 / 存储分开承担**：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 存储层 | `lib/store.js` | JSON 文件、原子写、故障注入、事务快照/回滚 |
| 领域层 | `lib/domain.js` | 认领(租约)、检查点续做、批次失效重排、入盒、幂等消耗、转手链事件 |
| 接口层 | `lib/api.js` | HTTP 路由，只做请求/响应 |
| 页面层 | `lib/page.js` | 持有人、租约倒计时、失效原因、重试结果、转手链时间线 |
| 入口 | `server.js` | 组装以上四层 |

## 运行

```bash
npm start
```

访问 `http://localhost:3040`。数据保存在 `data/cyanotype-negative-room.json`。

## 怎么演示

页面左侧与玻璃板卡片上的按钮即可走完：

1. **晚到覆盖**：一块板先由东窗「认领」，再用西窗认领 → 提示 `held_by_other`，持有人仍是东窗。
2. **跳步拒绝**：没做「涂布」就想「冲洗」→ 提示下一站是「涂布」，必须按检查点顺序来。
3. **过期续做**：认领后等 30s 租约过期，换一个工位「接管续做」→ 从最近检查点继续。
4. **批次失效**：左侧「更新药液批次」填一个新批次（如 `B-0715`）→ 旧显影结论变红失效、板状态变「待重洗」、持有被释放；重新认领后用新批次重冲洗，失效原因清除。
5. **写盘重试**：左侧「写盘故障注入」填 `2` 次失败，再记录检查点 → 重试结果面板显示 2 次失败后成功；该板药液消耗仍为 1 份，且持有人与完成记录同在。

## 接口

- `GET  /api/state` — 一次性返回工位、批次、玻璃板、转手链事件、重试遥测、故障配置
- `POST /api/plates` — 建档
- `POST /api/plates/:id/claim` — 认领 / 续租 / 过期接管（body: `{workstationId}`）
- `POST /api/plates/:id/checkpoint` — 记录工艺检查点（body: `{workstationId, step, ...}`）
- `POST /api/chemical-batches` — 更新药液批次，失效旧结论重排（body: `{code, note}`）
- `POST /api/faults` — 注入写盘故障（body: `{writeFailures, randomRate}`）
